〇、概述

本文梳理 Attention 推理优化：从 Online Softmax 的分块记账，到 FlashAttention、Flash-Decoding 与 FlashInfer，再到多卡 Ring Attention。Fused MoE 与变长处理另文记录。

一、Online Softmax

1.1 先分清：Softmax 和 Attention

Softmax：把一组实数转换为一组非负、总和为 1 的权重

给定一组有限实数 x=[x1,…,xN] ，先对每个数取指数，再除以所有指数之和：

pi=softmax(x)i=exi∑j=1Nexj,∑i=1Npi=1

Attention：计算注意力分数（attention scores），再用注意力权重（attention weights）对 V 加权求和

标准的缩放点积 Attention 公式是：

Attention(Q,K,V)=softmax(QK⊤d)V

其中 d 是 query、key 的维度，Softmax 对分数矩阵的每一行分别进行。只看一个 query q ，可以拆成三步：

注意力分数：si=q⊤kid注意力权重：pi=esi∑j=1NesjAttention 输出：o=∑i=1Npivi

注意力分数经过 Softmax 后，就得到注意力权重。如果分数仍为 [0,ln⁡2,0] ，注意力权重就是 [1/4,1/2,1/4] 。再对 V=[10,20,40] 加权，得到 o=14×10+12×20+14×40=22.5 。

把注意力权重 pi 代入输出公式，就能把「先归一化，再加权」改写成「先累计分子、分母，最后再除」：

o=∑ipivi=∑iesivi∑iesi

下面讲的是 Online Softmax 与乘 V 融合的过程。例子用标量 V 方便算数，实际 V 和输出都是向量。

1.2 分块到来，边读边记账

沿用上面的例子，假设每次只拿到一个 token 的 KV。算出它的分数后，只更新两笔账：

本次读到的数据 累计加权和（分子） 累计指数和（分母）
指数 1，V 为 10 10 1
指数 2，V 为 20 50 3
指数 1，V 为 40 90 4

全部读完，结果就是 90/4=22.5 。每次也可以读一整块 KV，分别求出这一块对分子、分母的贡献再累加。

**不需要保留看过的全部分数，也不用保存完整的注意力权重矩阵。**给这两笔账起个名字：累计分子叫 O ，累计分母叫 ℓ ，最终输出用小写 o=O/ℓ 表示。

1.3 为什么还要记一个最大值 m？

直接算 esi 可能溢出，例如 e1000 太大。解决方法是给分数统一减去最大值 m ：

o=∑iesi−mvi∑iesi−m

分子、分母同时乘了 e−m ，结果不变；而 si−m≤0 ，指数不会超过 1。

分块计算时还不知道最终最大值，所以先用已经看过的最大值。新块让最大值从 m 变成 m′ 时，旧账就要换到新尺度：

esi−m′=esi−m×em−m′

**也就是先把旧的 O 和 ℓ 同时乘 em−m′ ，再加新块的贡献。**若最大值没变，乘子就是 1。

1.4 把换尺度放回刚才的例子

第一条分数是 0，先记 m=0, ℓ=1, O=10 。第二条分数是 ln⁡2 ，最大值增大了，旧账要乘 e0−ln⁡2=1/2 ；第二条自己的指数则是 eln⁡2−ln⁡2=1 。

处理到哪条 当前最大值 m 累计分母 ℓ 累计分子 O
第一条 0 1 10
第二条 ln2 1×½ + 1 = 1.5 10×½ + 1×20 = 25
第三条 ln2（不变） 1.5 + ½ = 2 25 + ½×40 = 45

第三条分数是 0，在当前尺度下指数为 e0−ln⁡2=1/2 。最终 o=45/2=22.5 ，和原来的 90/4 完全相同。

1.5 最后再看公式和代码

每个 query 维护三个量：已见最大值 m 、累计分母 ℓ 、累计分子 O 。新块的分数为 S 、value 为 V ：

m′=max(m, max(S))α=em−m′ℓ′=αℓ⏟旧账换尺度+∑eS−m′⏟新块贡献O′=αO⏟旧账换尺度+eS−m′V⏟新块贡献

维度只需记住：对单个 head 的单个 query， S 是本块各 token 的分数向量， m,ℓ 是标量， O 和最终输出 o 是 value 维度的向量。 eS−m′V 就是用本块的指数对各个 value 向量加权求和。

二、FlashAttention-1（简述）

  • 循环：外循环 KV，内循环 Q。后向用重计算恢复 S/P。

  • 效果：显存 O(N2)→O(N) 。

  • 痛点：主要沿 (batch, head) 并行，小 batch、少 head 时并行度不足；外循环 KV 还需要反复读写输出和归一化状态。

三、FlashAttention-2（重点）

三个关键改动，核心目标：喂饱 tensor core + 更好并行。

外循环换成 Q

每个 thread block 认领一段 Qi ，内循环扫所有 KV。每个 block 独立维护 mi,ℓi,Oi ，无需跨 block 通信。HBM 写次数从 O(N/B⋅N/B) 降到 O(N/B) 。

沿 Q 维额外并行

给定 Q/K/V 后，每个 qi 的输出只依赖它自己和可见的 K/V，不依赖其他 query 的输出，因此可以把不同的 query 分给不同 thread block。

FA-1 只按 (batch, head) 并行。FA-2 额外沿 sequence 维并行（Q 之间独立）。长序列 + 小 batch 时 SM 占用率大幅提升。

thread block 与 SM：CUDA 的线程组织是 grid → thread block → thread。一个 block 在一个 SM 上执行，block 内线程可以通过 shared memory 协作。这里不同 query 的 block 各自累计自己的输出，无需彼此交换计算结果。

减少非 matmul FLOPs

逐步除 ℓ 推迟到最后，中间只维护未归一化的 O。H100 上 tensor core 是非 tensor core 的 ~16×，减少 non-matmul 立竿见影。

Warp 布局

FA-1 split-K（K 维切给不同 warp，需通信合并）→ FA-2 split-Q（每个 warp 拿整段 Q 行，K/V 共享，warp 间零通信）。

四、FA-3 / FA-4（简述）

FA-3（Hopper H100）

WGMMA + TMA + warp specialization（生产者搬数据，消费者算 GEMM，软流水）。GEMM 与 softmax exp 重叠执行。引入 FP8。

FA-4（Blackwell）

跳过已知 m 不变时的 rescale；每线程处理一整行省 shuffle；两个 softmax warpgroup 显式同步。

五、Ring Attention：多张卡接力传 KV

只看推理：CP（上下文并行）决定怎么切序列，Ring Attention 决定切完后怎么计算 Attention，Online Softmax 负责正确累计分块结果。

长输入的 Prefill 阶段，可以把同一条序列 沿 token 维度分给多张 GPU。但本地 query 仍需要看到其他卡上的可见 KV。Ring Attention 的做法是：Q 留在本卡，KV 沿环传递，收到一块就计算一块，更新本地的 (m,ℓ,O) 。

先忽略因果掩码，以 3 张卡为例：

每张卡都像第一节那样“边收边记账”，全部处理完再计算 o=O/ℓ 。各卡为自己的 query 分别算分数

它不必在每张卡上同时保存完整 KV，还可以重叠计算与通信；标准稠密 Attention 的总计算量仍是平方级。原论文

带因果掩码时，越靠后的 query 要看越多历史 token。可用 Zigzag 分配让轻重任务互补，例如 4 张卡各拿两块：(0,7)、(1,6)、(2,5)、(3,4)；位置编码和掩码仍按原始位置处理。

六、FlashInfer

FA 是"高性能函数"，FlashInfer 是"高性能运行时"：它内含 FA 级别的 attention kernel，但额外解决 serving 场景才有的三个问题。

6.1 paged KV cache

Serving 时每个请求长度不同且动态增长，KV cache 常用 paged 格式（切成固定页、page table 索引）。代价是 KV 物理上不连续，普通 FA kernel 要先拷成连续 tensor 才能算。FlashInfer 的 kernel 直接读 paged 格式，省掉拷贝。

怎么做的：加一层间址

load 每个 KV tile 前先查一次 page table 拿到物理页号再算地址，tile 内部计算完全不变。这套间址统一成 block-sparse 抽象（paged、变长、causal mask 都只是不同索引）。代价是多一次查表，但省掉 decode 每步的整块拷贝。

6.2 变长负载均衡

同一 batch 里序列长度差距很大（100 vs 100k）。decode 阶段每个请求只有 1 个 query token，query-tile 维度塌了，只剩 (batch, head) 可并行——每个 (请求, head) 一个 thread block、串行扫完自己全部 KV。于是 100 的 block 秒完空闲、100k 的 block 独占一个 SM 扫上千步，成为瓶颈。

集成 Flash-Decoding

既然 query 维切不动，就沿 KV 维再切一刀——把长序列的 KV 切成多个 chunk 丢给不同 SM 并行扫，各产出局部 (m, ℓ, O)，最后用 online softmax 合并（和 block 间在线累积同一套数学）。长序列的活儿由此摊到多个 SM，SM 不再干等。

6.3 attention 变体统一

causal、sliding-window、GQA、MQA 等变体太多。FlashInfer 用参数化 CUDA 模板 + JIT：首次遇到新配置即时编译并缓存复用，不用为每种组合手写 kernel。
